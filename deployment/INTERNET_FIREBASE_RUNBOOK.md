# Internet hosting and account persistence — V75.251
This is a deployment runbook, not evidence of a live service.

## Required infrastructure
- A Linux host able to run the imported Godot 4.7.2 headless project and Node 22; a public DNS hostname pointing to it, trusted TLS certificate and inbound TCP 24621. Use a trusted certificate with the full chain and secure private key storage. Do not expose ENet development ports.
- Firebase project with the existing Android package, exact OAuth web client, signing SHA fingerprints, Google and Anonymous providers, Play Integrity and App Check. Native Gradle APK only; the old non-Gradle preview cannot authenticate.
- A dedicated least-privilege runtime service account with Firestore access, Application Default Credentials, and secret access for the room worker. Never copy service-account JSON or a signing key into the APK/repository. CI does not deploy production functions.
- Existing callable deployments must be verified; deploy the specific new callables only after staging verification, using the Firebase CLI with explicit project selection and credentials. Configure AURORA_MATCH_SIGNING_KEY as a 32-byte random hex secret in Secret Manager and inject the same value into the trusted worker, not into any client. This shared-key design should be replaced by per-fleet asymmetric tickets before wide production.
- Register and start the worker using deployment/aurora-room.service; copy code and imported resources to /opt/aurora, install Node dependencies, create a non-root aurora user, and provision /etc/aurora/room.env (root-readable only), TLS files readable by that service account, and a stable public endpoint. Set AURORA_PUBLIC_ENDPOINT=wss://YOUR-DNS:24621, AURORA_MODE=solo, AURORA_TLS_CERT, AURORA_TLS_KEY, GODOT_BIN, AURORA_MATCH_SIGNING_KEY and ADC by workload identity. Do not publish a placeholder endpoint.
- systemd restarts the single-use worker after room closure. One process accepts at most four humans and fills to 50 bots; multiple simultaneous rooms need distinct endpoints/ports and independent workers, plus fleet orchestration. WSS is reliable TCP; test under real cellular latency before release.
- Online records now persist transactionally from trusted room results only; one receipt per room prevents repeat credits. User identity is bound through a hashed Firebase UID and sealed roster, not chosen by clients. GetOnlineStats is App Check protected. Nickname writes use existing revision-checked callable. Unranked stats and local progress remain separate. Currency, cosmetics, friends, cross-region scaling, durable retry after abrupt host failure and competitive ranking are not complete.
- On a real device sign in via Google, change nickname, finish a room, log out, and sign into the same Google account on another device; verify the same official ID/name and online stats. Verify rejected auth, stale ticket, untrusted TLS and cellular access. Never call the service production-ready before this.
