# V75.251 — Internet admission candidate
V75.250 is the immediate parent, still in CI when work began; latest confirmed Android release V75.249. Protocol 31. No LAN option in the lobby. Internet button invokes the real Firebase Android SDK callable (Auth + App Check), selects a live server-owned room with transactional reservations and returns a single-use short-lived signed ticket. TLS WebSocket transport uses certificate validation; Godot SceneMultiplayer authenticates before gameplay RPCs. No Firebase credentials passed to the game or printed. Worker registers actual open/sealed/closed room with heartbeat in restricted Firestore collections; start only with ADC, trusted TLS certificate, public DNS endpoint, correct secret, and a host that can run Godot. Source-only deployment preparation: no cloud resource created, no production functions deployed, no signing key generated, no billing change. Android export now requires existing Firebase config and includes native plugin in the same signed Vulkan artifact. Tests cover ticket signing, rejection, real TLS loopback and snapshot after admission; no WAN or Android physical tests. WSS is reliable TCP; latency/loss under WAN must be measured before declaring it production-ready. Registry allocates existing servers only, no autoscaling or durable ranked rewards, no global region fleet yet. Matchmaking UI requests solo; server worker can configure team modes but they are not selectable from client yet.
